# v0.15.0 Release Notes

**Release Date:** 2026-10-05

## Highlights

- **dashboardir Import Fixed** - The `uiforge` package's `dashboardir` import and the dashboard schema URL moved from `plexusone/uiforge` back to `plexusone/dashforge`, matching the module path's actual history (`dashforge` → `uiforge` → `dashforge`) and fixing an unresolvable dependency version on the Go proxy

## Breaking Changes

- `uiforge/converter.go` and `uiforge/widgets.go` now import `github.com/plexusone/dashforge/dashboardir` instead of `github.com/plexusone/uiforge/dashboardir`. Any caller type-asserting on `dashboardir.Dashboard` or other `dashboardir` types (for example, values returned from `uiforge.DashboardSet`) must update its import to match.

## Dependencies

- Replaced `github.com/plexusone/uiforge v0.5.0` with `github.com/plexusone/dashforge v0.7.0` — `uiforge v0.5.0` is unresolvable on the Go proxy (the `plexusone/uiforge` module path carries versions from before a prior rename; `dashboardir` itself never lived there)
- Updated `github.com/grokify/prism-roadmap` to v0.21.0
- Updated `golang.org/x/text` to v0.42.0
- Updated `github.com/modelcontextprotocol/go-sdk` to v1.8.0

## Context

This mirrors the same fix already applied to `devfolio`: the `plexusone/uiforge` module path was `dashforge` through v0.3.0, renamed to `uiforge` for v0.4.0–v0.5.0, then renamed back to `dashforge` for v0.6.0–v0.7.0, before a new, unrelated `uiforge` project claimed the path starting at v0.8.0. Anything pinned to `uiforge` v0.1.0–v0.7.0 — including this package's prior `v0.5.0` requirement — points at stale, pre-rename content or a version the Go proxy no longer serves.
